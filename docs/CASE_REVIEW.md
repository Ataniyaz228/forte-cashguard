## Суть и обязательный результат

Нужен работающий сервис анализа видеозаписей кассы. Пользователь загружает новый ролик в веб-интерфейсе, видит статус и результат. Для каждого возможного нарушения сервис выдаёт тип, таймкод, описание наблюдаемого действия, кадры-доказательства и нормативное основание. Событий в одном видео может быть несколько. Результат помогает человеку проверить ситуацию, не является юридическим или дисциплинарным заключением.

Это задача анализа действий во времени и локализации событий. Табличный прогноз или единственный ответ «есть нарушение» не закрывает задание. Нельзя утверждать невидимое: корректность проводки, состояние АБИС, системную сверку. Типы событий команда определяет сама и связывает с проверенными источниками РК.

Раздел 10: жюри проверяет видео через публичный API и только затем приглашает шортлист на питч. Следовательно, исправный API и качество результатов нужны до выступления. Питч: 5 минут и 2 минуты вопросов, слайды по желанию; при равенстве баллов учитывается питч (FAQ 19–20).

## Контракт API

| Метод | Путь | Контракт |
|---|---|---|
| POST | `/api/v1/analyze` | `.mov` в multipart-поле `file`; ответ с `job_id` |
| GET | `/api/v1/jobs/{job_id}` | Статус `processing`, `done`, `failed`; при готовности результат |

Обязателен `X-API-Key`, неверный или отсутствующий ключ отклоняется. Команда передаёт жюри адреса UI/API и ключ; ключ не публикуется в репозитории.

Готовый результат: `job_id`, `status`, `verdict`, `violations`. Вердикт только `no_violation` или `violation`; без событий список пуст. Каждое событие содержит `type`, `timecode_sec`, `description`, `evidence_frames`; кадр содержит `timestamp_sec`, `image_base64`. На событие нужно 1–3 JPEG в base64. Время — секунды от начала ролика.

Сервис недоступен или нет результата за 5 минут — видео считается необработанным. Не уточнены отсчёт от начала/конца загрузки, учёт очереди и число параллельных запросов. Консервативный бюджет от приёма запроса — возможное инженерное решение, не официальное уточнение.

## Ограничения

1. Все модели выполняются внутри сервиса команды. Облачные AI API запрещены при обработке видео, включая передачу кадров и описаний. Запрет касается не только сырых файлов.
2. После скачивания весов inference не должен требовать интернета. Публичный URL и локальное исполнение моделей — разные требования; публичный доступ обязателен.
3. GPU и облачные кредиты организаторы не дают. Допустимость удалённого сервера команды и транспортного туннеля отдельно не раскрыта.
4. Анализ строго визуальный; звук, распознавание и идентификация лиц запрещены.
5. Подготовленный код, шаблоны и предобученные модели разрешены при open source и лицензии с коммерческим использованием (FAQ 24). Лицензии кода и весов нужно проверять отдельно.
6. FAQ 35 запрещает «готовые решения», но не определяет термин. Нельзя автоматически считать любую разрешённую предобученную модель запрещённым готовым продуктом.
7. ForteBank оставляет за собой право коммерчески использовать решение (FAQ 34). Более широкую передачу исключительных прав из этой фразы не выводим.

Авторизация пользователей, история, экспорт отчётов и пакетная загрузка не требуются. Это не отменяет обязательный API-ключ жюри. Язык интерфейса и объяснений выбирает команда.

## Соответствие подготовленного набора

До обновления заметок проверены 45 файлов подготовленного ZIP: побайтово совпадали с проектом. Пригодятся Python, Jupyter, воспроизводимость и шаблоны слайдов. CatBoost pipeline, табличные split и CSV submission не реализуют этот кейс. Прежний совет «деплой — бонус» здесь неприменим: URL и UI обязательны. Основная защита — 5 минут, версия на 2 минуты остаётся тренировочной. Старые документы с фразой «кейс неизвестен» отражают подготовительный этап; актуальные требования находятся здесь и в `REQUIREMENTS.md`.

Проверка среды без установки: FFmpeg/ffprobe есть; RTX 4050 — около 6 ГБ VRAM, при проверке свободно около 5.6 ГБ; диск — около 33 ГБ свободно. В `.venv` нет PyTorch, Transformers, OpenCV, PyAV и FastAPI. Модель и производительность ещё не проверены; сначала нужен выбор подхода по данным, затем адаптация окружения.

## Вывод

Следующий шаг — локально исследовать действия на видео, определить проверяемые события, найти применимые источники и оценить подход на отдельных роликах/сценариях, включая другой ракурс. Соседние кадры одного видео и побайтовые копии роликов не подходят для независимой проверки.

Наше предполагаемое преимущество — цепочка «наблюдаемое событие → точный фрагмент → доказательство → проверенное правило», особенно на новом ракурсе и неизвестном событии. Это стратегия по рубрике, не гарантия результата. Конкретные классы, модель и архитектура пока не выбраны.
