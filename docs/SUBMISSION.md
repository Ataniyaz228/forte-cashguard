# CashGuard — сервис проверки кассовой дисциплины по видео

Черновик комплекта сдачи по разделу 8 ТЗ. Адреса, ключ и итоговые метрики заполняются перед сдачей.

## 1. Адреса и доступ

| Что | Значение |
|---|---|
| Веб-интерфейс | `[URL]` |
| API | `[URL]/api/v1/analyze`, `[URL]/api/v1/jobs/{job_id}` |
| API-ключ жюри | передаётся отдельно, заголовок `X-API-Key` |

```bash
curl -X POST [URL]/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video.mov"
# {"job_id":"…","status":"processing"}
curl [URL]/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
```

Ответ `done` содержит обязательные поля `job_id`, `status`, `verdict`, `violations`. Каждое событие имеет `type`, `timecode_sec`, `description`, `evidence_frames` (1–3 JPEG в base64 с `timestamp_sec`). Дополнительные поля события: `type_code`, `confidence`, `rule` (документ, пункт, текст, ссылка). Строгий парсер может их игнорировать. Нормативная ссылка продублирована в `description`.

## 2. Запуск и использование

```bash
uv sync                                   # Python 3.12, зависимости из uv.lock
echo "CASHGUARD_API_KEYS=<ключ>" >> .env  # ключ не хранится в git
.venv/bin/python -m datathon.cashguard serve --port 8000
.venv/bin/python -m datathon.cashguard analyze video.mov --no-images   # локальная проверка
```

Веса моделей скачиваются один раз в кеш Hugging Face. После этого обработка работает без интернета (`HF_HUB_OFFLINE=1`). Пользователь открывает веб-страницу, загружает `.mov`, видит статус, вердикт и карточки событий. В каждой карточке тип, таймкод (по клику видео перематывается), описание, основание и кадры. Авторизация, история и экспорт не требуются (FAQ 27). API жюри защищено ключом.

## 3. Архитектура и подход

```
.mov → декодирование по реальным PTS
     ├─ 3 кадра/с → RT-DETR (люди, ноутбук) → временная линия: сколько людей, вход/выход,
     │                                        сидит/стоит → уход с рабочего места
     │            → доля «светящегося» экрана в боксе ноутбука → экран заблокирован или нет
     └─ 0,5 кадра/с → Qwen3-VL-2B: вопросы «да/нет» о сцене, ответ — P(yes) из логитов
                      (сейф открыт, наличные/сумка/документы на столе, показ удостоверения…)
→ временные правила (rules.py) → события с таймкодом и уверенностью
→ отчёт: тип, нормативное основание, фактическое описание по шаблону, кадры-доказательства
```

- **Почему не одна обученная модель.** 40 уникальных роликов, по 1–2 примера на тип, тест под другим углом. Сквозное обучение здесь переобучится. Детектор и VLM работают без дообучения под конкретную камеру, а логика нарушений записана явно и проверяется.
- **Почему описания по шаблону.** Критерий 4 штрафует неподтверждённые утверждения. Текст собирается только из измеренных фактов (время ухода, что осталось на столе) и дословной нормы. Свободная генерация не используется.
- **Таймкод.** Как в разметке организаторов: момент, когда нарушение становится видно (кассир встаёт и уходит, входит следующий посетитель). Для нарушения по бездействию — момент, где обязательное действие должно было произойти.
- **Расширяемость.** Новый тип = новый вопрос к VLM + правило + запись в `norms.py`. Переобучение не нужно.

## 4. Модели и лицензии

| Компонент | Модель | Лицензия |
|---|---|---|
| Детектор объектов | `PekingU/rtdetr_r50vd_coco_o365` (RT-DETR) | Apache-2.0 |
| Визуально-языковая модель | `Qwen/Qwen3-VL-2B-Instruct` | Apache-2.0 |
| Фреймворки | PyTorch (BSD-3), Transformers (Apache-2.0), PyAV (BSD-3), FastAPI (MIT) | — |

Все модели выполняются внутри сервиса на нашей машине. Облачные AI-API не используются. Звук не анализируется, лица не распознаются и не идентифицируются.

## 5. Нормативные источники и сопоставление

Тексты проверены на официальном портале ИПС «Әділет» 17.10.2026:

- Постановление Правления НБРК от 29.11.2019 № 231 — Правила кассовых операций и инкассации: п. 12, п. 19 подп. 2, п. 20, п. 22, п. 24, п. 75.
- Постановление Правления НБРК от 24.02.2020 № 14 — Правила охраны и устройства помещений: п. 8, п. 16 подп. 1.
- Для блокировки экрана норма в актах НБРК не найдена. Используется мера «чистый стол и чистый экран» стандарта СТ РК ISO/IEC 27002 (пересказ, не цитата). FAQ 31 допускает источники без точного пункта.

Принцип: правило срабатывает только по видимому действию или состоянию. Норма приводится как основание для проверки, а не как установленный факт нарушения. Невидимое (проводки, учёт, подлинность банкнот) сервис не утверждает.
